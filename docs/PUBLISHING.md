# Source handoff and GitHub

Share the ZIP generated by `scripts/package_release.py`, or the source directory
without its ignored data/model/run folders. The archive has a SHA256 manifest
and verifies member contents before reporting success.

To publish from this directory after choosing your repository name/visibility:

```bash
git init -b main
git add README.md run.py .gitignore requirements-*.txt training scripts tests docs licenses THIRD_PARTY_NOTICES.md
git status --short
git commit -m "Prepare portable STRIDE training handoff"
```

Create an empty repository in your own GitHub account or organization. Then set
its actual URL (replace the example below) and push:

```bash
git remote add origin https://github.com/YOUR_ORG/YOUR_REPOSITORY.git
git push -u origin main
```

Do not upload `models/`, `data/`, `runs/`, downloaded credentials, `.venv/` or
`.cache/`. They are ignored by the supplied `.gitignore`; the release packager
uses a separate source allowlist. Preserve the inherited Apache notices. The
authors have not yet selected a license for their own STRIDE code; see
`THIRD_PARTY_NOTICES.md`.

Publication does not imply all planned baselines or four external benchmark
integrations are implemented. Keep the README's implementation and validation
limits with the source.
